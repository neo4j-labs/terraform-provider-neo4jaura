TASK-001: Make AuraClient base URL configurable via AURA_BASE_URL env var
Date: 2026-05-08T22:30:00Z
================================================================================

Summary:
Added a `baseURL string` parameter to `NewAuraClient`. When empty, it defaults
to `https://api.neo4j.io`. The resolved URL is stored on both `AuraClient` and
`AuraAuth` so that `doOperation` builds API URLs from `c.baseURL` and
`authenticate` builds the OAuth token URL from `a.baseURL`. The provider's
`Configure` method reads `AURA_BASE_URL` from the environment and passes it
through. The existing test helper `newTestAuraApi` in `neo4j_utils.go` was
updated to pass the same env var.

Files Changed:
- internal/client/aura_client.go (modified: replaced auraBasePath/auraV1Path constants with defaultAuraBasePath; added baseURL field to AuraClient; updated NewAuraClient signature; doOperation uses c.baseURL)
- internal/client/aura_auth.go (modified: added baseURL field to AuraAuth; authenticate uses a.baseURL instead of removed constant)
- internal/provider/provider.go (modified: import "os" added; NewAuraClient call passes os.Getenv("AURA_BASE_URL"))
- internal/test/neo4j_utils.go (modified: NewAuraClient call updated to 4-arg signature, passes os.Getenv("AURA_BASE_URL"))

Key Decisions:
- Kept `defaultAuraBasePath` constant in aura_client.go as the single source of truth for the default URL; AuraAuth receives the already-resolved URL at construction time (no second default needed in auth).
- `AURA_BASE_URL` is read at provider Configure time (not at package init), so tests can set it before constructing the provider.

================================================================================
TASK-004: Implement mock snapshot and tenant endpoints
Date: 2026-05-08T23:10:00Z
================================================================================

Summary:
Implemented four stub handlers in internal/test/mock_server.go for snapshot and
tenant endpoints. Added `time` and `domain` imports.

- handleGetTenants: returns 200 with GetProjectsResponse containing one preset
  project {Id: "test-project-id-001", Name: "Test Project"}.
- handlePostSnapshot: generates a snap-<nanosecond> ID, stores a GetSnapshotData
  entry in ms.snapshots with getCount=0, Profile=Scheduled, Status=InProgress,
  and Timestamp=RFC3339 now. Returns 202 with PostSnapshotResponse.
- handleGetSnapshots: iterates ms.snapshots filtering by instanceId, returns 200
  with GetSnapshotsResponse (empty array when none found).
- handleGetSnapshot: increments getCount under the mutex; returns InProgress on
  first call (getCount==1), Completed on second and subsequent (getCount>=2).
  Returns 404 if snapshotKey not found. Returns 200 with GetSnapshotResponse.

All map access holds ms.mu. The instance-endpoint stubs (task-003) were not
touched.

Files Changed:
- internal/test/mock_server.go (modified: added time/domain imports; implemented
  handleGetTenants, handlePostSnapshot, handleGetSnapshots, handleGetSnapshot)

Key Decisions:
- getCount starts at 0 for POST-created snapshots so that the first GET
  increments to 1 (InProgress) and the second increments to 2 (Completed),
  matching the state-machine contract in the task description.
- SeedSnapshot continues to initialise getCount=1 so that a seeded snapshot
  is already "past" the first GET and returns Completed on the first test GET,
  which is the expected behaviour for import tests.
- nil-slice guard in handleGetSnapshots ensures the JSON response is always
  an array ([]) rather than null when no snapshots exist.
