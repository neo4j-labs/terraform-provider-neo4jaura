TASK-002: Conditionalize PATCH calls in InstanceResource.Update (D-03)
Date: 2026-05-11T11:42:00Z
================================================================================

Summary:
Refactored InstanceResource.Update to only issue each PATCH call when the
corresponding fields actually changed. Previously, both the name/memory PATCH
and the secondaries_count PATCH were issued unconditionally whenever either
changed. Now the name/memory PATCH is guarded by `planNameOrMemoryChanged`
and the secondaries_count PATCH by `planSecondariesChanged`. When the
secondaries PATCH fails after the name/memory PATCH already succeeded, the
error message clearly states which update succeeded.

Files Changed:
- internal/resource/instance.go (modified: conditionalized PATCH calls in Update)
- .changes/unreleased/fix-conditional-patch-in-update.yaml (created: changelog entry)

Key Decisions:
- Used a `nameMemoryUpdateSucceeded` boolean (set at runtime after success) rather
  than just reusing `planNameOrMemoryChanged`, to correctly track whether the
  API call actually completed vs. just being planned.
- The WaitUntilInstanceIsInState call uses plan name/memory values; when only
  secondaries_count changed, these equal the current state values, so the
  condition is met without a real wait — correct behavior.

TASK-003: Fix sort antisymmetry in readMostRecentSnapshot and add ctx to WaitUntil (D-04, D-05)
Date: 2026-05-11T14:33:00Z
================================================================================

Summary:
D-04: Fixed sort antisymmetry in readMostRecentSnapshot by replacing the
`return true` on parse error with a closure-captured `sortErr` variable. The
comparator now returns `false` on error and subsequent calls short-circuit via
`if sortErr != nil { return false }`. After sort, `sortErr` is checked and
surfaced as a Terraform diagnostic rather than silently producing undefined order.
D-05: Added `context.Context` as the first parameter to `WaitUntil` and replaced
`time.Sleep(delay)` with a `select` on `ctx.Done()` so Terraform plan/apply
cancellations are respected during polling wait intervals. All 4 callers in
`aura_api.go` updated to pass `ctx`.

Files Changed:
- internal/datasource/snapshot.go (modified: sort error capture pattern in readMostRecentSnapshot)
- internal/util/waiter.go (modified: added ctx param, replaced time.Sleep with select)
- internal/client/aura_api.go (modified: added ctx as first arg to all 4 WaitUntil calls)
- .changes/unreleased/fix-sort-antisymmetry-in-read-most-recent-snapshot.yaml (created: changelog entry)
- .changes/unreleased/fix-wait-until-context-cancellation.yaml (created: changelog entry)

Key Decisions:
- Closure-captured `sortErr` is the idiomatic pattern for surfacing errors from `sort.Slice` comparators, which cannot return errors directly.
- `time.After` in the select creates a new timer each iteration; acceptable for polling intervals of 1+ seconds.

(source snapshot wait) and one in SnapshotResource.Create.

Key Decisions:
- `strings.ToLower(domain.SnapshotStatusCompleted)` is evaluated at runtime each polling tick.

  No performance concern at polling intervals of seconds.
