TASK-002: Conditionalize PATCH calls in InstanceResource.Update (D-03)
Date: 2026-05-11T11:42:00Z
================================================================================

Summary:
Refactored InstanceResource.Update to only issue each PATCH call when the
corresponding fields actually changed. Previously, both the name/memory PATCH
and the secondaries_count PATCH were issued unconditionally whenever either
changed. Now the name/memory PATCH is guarded by `planNameOrMemoryChanged`
and the secondaries_count PATCH by `planSecondariesChanged`. When the
secondaries PATCH fails after the name/memory PATCH already succeeded, the
error message clearly states which update succeeded.

Files Changed:
- internal/resource/instance.go (modified: conditionalized PATCH calls in Update)
- .changes/unreleased/fix-conditional-patch-in-update.yaml (created: changelog entry)

Key Decisions:
- Used a `nameMemoryUpdateSucceeded` boolean (set at runtime after success) rather
  than just reusing `planNameOrMemoryChanged`, to correctly track whether the
  API call actually completed vs. just being planned.
- The WaitUntilInstanceIsInState call uses plan name/memory values; when only
  secondaries_count changed, these equal the current state values, so the
  condition is met without a real wait — correct behavior.
