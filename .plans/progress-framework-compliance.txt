TASK-001: Add ErrNotFound sentinel to AuraClient and handle 404 in Read
Date: 2026-05-11T15:50:00Z
================================================================================

Summary:
Introduced a sentinel ErrNotFound error in the client package and updated both
InstanceResource.Read and SnapshotResource.Read to call response.State.RemoveResource(ctx)
on 404, enabling Terraform drift detection and planned recreation instead of hard errors.

Files Changed:
- internal/client/aura_client.go (added ErrNotFound sentinel using errors.New)
- internal/client/aura_api.go (GetInstanceById and GetSnapshotById return fmt.Errorf with %w wrapping ErrNotFound on HTTP 404)
- internal/resource/instance.go (Read uses errors.Is(err, client.ErrNotFound) → RemoveResource)
- internal/resource/snapshot.go (Read uses errors.Is(err, client.ErrNotFound) → RemoveResource)
- .changes/unreleased/errnotfound-404-read.yaml (changelog entry)

Key Decisions:
- ErrNotFound lives in aura_client.go alongside the transport layer, not aura_api.go, keeping the sentinel close to the HTTP layer
- fmt.Errorf with %w preserves errors.Is chain through wrapping (includes resource ID in message for debuggability)
- Both GetInstanceById and GetSnapshotById handle 404 explicitly before the generic non-200 error path
- WaitUntilInstanceIsDeleted correctly polls for status==404 at the raw HTTP level and is unaffected by this change

TASK-003: Add env var fallback for credentials and fix registry address
Date: 2026-05-11T16:00:00Z
================================================================================

Summary:
Updated provider.Configure to fall back to AURA_CLIENT_ID and AURA_CLIENT_SECRET
environment variables when the HCL provider block attributes are null/unknown/empty,
matching the existing AURA_BASE_URL pattern. Changed client_id and client_secret schema
attributes from Required to Optional to allow omitting them when env vars are set.
Updated main.go registry address to the production value.

Files Changed:
- internal/provider/provider.go (client_id/client_secret Required→Optional; Configure reads AURA_CLIENT_ID and AURA_CLIENT_SECRET as fallback)
- main.go (Address updated from "terraform.local/local/aura" to "registry.terraform.io/neo4j-labs/neo4jaura")
- .changes/unreleased/env-var-credentials-registry-address.yaml (changelog entry)

Key Decisions:
- Fallback logic uses IsNull() || IsUnknown() || == "" — same triple-guard used for AURA_BASE_URL — so any non-value config state correctly defers to the env var
- HCL values always take precedence: env var is only read when the HCL value is absent or empty
- Schema attributes changed to Optional (not Optional+Computed) — there is no API that can "read back" these credentials, so Computed would be incorrect
- Provider does not error when credentials are missing entirely; that error will surface at the first API call (consistent with how AURA_BASE_URL works)

TASK-005: Add update test, disappears test, PreCheck, and CheckDestroy
Date: 2026-05-11T16:45:00Z
================================================================================

Summary:
Added testAccPreCheck (wired into every resource.TestCase), testAccCheckInstanceDestroyed
(a factory that checks the mock server, wired into every instance TestCase), and two new
tests: TestAcc_instance_update (two-step name change, in-place) and
TestAcc_instance_disappears (out-of-band delete via mock, ExpectNonEmptyPlan). Also made
Delete idempotent by treating ErrNotFound as success.

Files Changed:
- internal/test/provider_test.go (added testAccPreCheck; added terraform-plugin-testing/helper/resource import)
- internal/test/assertions.go (added testAccCheckInstanceDestroyed factory + deleteInstanceOutOfBand helper; added terraform import)
- internal/test/mock_server.go (added InstanceExists and DeleteInstance methods)
- internal/test/instance_resource_test.go (wired PreCheck+CheckDestroy into all TestCases; added TestAcc_instance_update and TestAcc_instance_disappears)

- internal/test/snapshot_resource_test.go (wired PreCheck)
- internal/test/snapshot_test.go (wired PreCheck)
- internal/client/aura_api.go (DeleteInstanceById returns ErrNotFound on HTTP 404)
- internal/resource/instance.go (Delete treats ErrNotFound as success; added early return after non-404 error)
- .changes/unreleased/acceptance-test-precheck-checkdestroy-update-disappears.yaml (changelog entry)

Key Decisions:
- testAccCheckInstanceDestroyed is a factory func(*MockServer) so it can be defined in non-test assertions.go while still accessing mock state; call sites pass testMockServer
- CheckDestroy receives state *before* destroy (by framework design), so we look up instance_id from attributes and query the mock rather than checking Terraform state emptiness
- InstanceExists / DeleteInstance are public methods on MockServer protected by mu, safe for concurrent sub-tests
- deleteInstanceOutOfBand reads instance_id from state attributes (not rs.Primary.ID which is always "id-attribute-not-set" for this resource)
- TestAcc_instance_disappears uses a single step with ExpectNonEmptyPlan: true — the out-of-band delete in Check triggers a non-empty post-step refresh plan; no second step needed
- Delete idempotency (ErrNotFound → return) is required so the disappears test's post-test cleanup doesn't fail when Terraform tries to destroy an already-gone instance
